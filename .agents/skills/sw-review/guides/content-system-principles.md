## Why this guide exists

The Content System (`src/Core/Framework/ContentSystem/`, `src/Storefront/ContentSystem/`) and its editor, the Experience Studio module in the Administration, are designed around written principles: one file per area under [docs/principles/](../../../../src/Core/Framework/ContentSystem/docs/principles/README.md#index), each with the rule, a `Why` line, a `Decided against` line, the documented exceptions and the code that pins it. The module's [AGENTS.md](../../../../src/Core/Framework/ContentSystem/AGENTS.md#constraints) asks every change to be checked against the principle file of its area. A review that reads only the diff cannot do that check, because the principles live next to the code, not in the coding guidelines, so this guide brings them into the review. The principles are the authoritative text; this guide only says where to look and what a violation looks like.

## Check

Before the rules: open [docs/principles/README.md](../../../../src/Core/Framework/ContentSystem/docs/principles/README.md#index), pick the area files that the changed paths touch (the "By area" list names them, the "By task" list routes by symptom), and read each file whole, including its `Exceptions` paragraph. Cite the file and the heading in every finding. Where the principle file and this guide differ, the principle file wins.

- **CSP-001** Look for a change that contradicts a rule, a `Why` line or a `Decided against` line of the principle file of its area, and is not covered by that file's `Exceptions` paragraph. Examples of such contradictions: a first-wins pick that resolves an ambiguous declaration, a malformed registry row that is skipped and logged, a layout polymorphic over root sources, a second client type for the element shape. The principles record decisions that were made once and reversed costs; a change that reopens one needs the principle file changed in the same PR, with its `Why` updated, not a silent exception. Rule: [AGENTS.md constraints](../../../../src/Core/Framework/ContentSystem/AGENTS.md#constraints), [principles index](../../../../src/Core/Framework/ContentSystem/docs/principles/README.md#index). Example: none recorded yet.
- **CSP-002** Look for a rule change without its pinning test, or a pinning test weakened without the rule changing. Each principle names the class or test that enforces it under `In code`; a change to the rule, to that test and to the governed code belongs in one commit, so the rule cannot drift from the code. Flag a changed `docs/principles/*.md` rule whose pinning test is not in the diff, and a changed pinning test (for example `ContentSystemExceptionTest`, `StoredTreeShapeConformanceTest`, `ContentLayoutDefaultSeedingTest`, `ElementIdRuleTest`) whose principle file is not. Rule: [AGENTS.md constraints](../../../../src/Core/Framework/ContentSystem/AGENTS.md#constraints). Example: none recorded yet.
- **CSP-003** Look for a component that degrades instead of throwing: a `catch` that returns null, an empty array or a stale value; a coercion or clamp of an invalid value (`max(1, $size)`, `(string) $key`, `?? $default` on a rejected input); a value-domain check loosened to make a suite pass; a loader that skips a declaration or invents a name for it. The module fails fast at the point where it meets invalid data, because a degraded result that looks valid cannot be told from a correct one. The documented exceptions are narrow: mapping fallbacks, a loader's not-found on a collaborator's HTTP exception or an invalid UUID, the Storefront catching the outer failure. Rule: [A component throws where it meets invalid data, and nothing degrades silently](../../../../src/Core/Framework/ContentSystem/docs/principles/failure-and-loss.md#a-component-throws-where-it-meets-invalid-data-and-nothing-degrades-silently), [A declaration or registration defect fails the container build or the registry load](../../../../src/Core/Framework/ContentSystem/docs/principles/failure-and-loss.md#a-declaration-or-registration-defect-fails-the-container-build-or-the-registry-load-before-any-request-uses-the-declaration). Example: `ResolvedValueIndexEncoder` throws on a missing index because an empty map would look like a page whose elements resolved nothing; `SlicedDistributionConfig` rejects a slice size below 1 instead of clamping it.
- **CSP-004** Look for a loss that the response does not report, or a defect code outside the pinned set. A mutation that detaches a child must return it as orphaned and name every dropped property and wiring key; a request DTO that accepts extra attributes, or a route that strips an undeclared field instead of answering 400, hides the loss from the editor. A new client-defect code must enter `CLIENT_DEFECT_CODES`, the pinned test, the documentation and the Administration's `structuralErrorCodes` in the same change; a second code for one condition, or a changed value of an existing code, is a break for every consumer. For the ux persona: an editor change that discards orphaned children or dropped names from the mutation response promotes silent loss. Rule: [The module drops nothing silently and reports every loss](../../../../src/Core/Framework/ContentSystem/docs/principles/failure-and-loss.md#the-module-drops-nothing-silently-and-reports-every-loss), [One exception class holds a closed, pinned set of client-defect codes](../../../../src/Core/Framework/ContentSystem/docs/principles/failure-and-loss.md#one-exception-class-holds-a-closed-pinned-set-of-client-defect-codes). Example: none recorded yet.
- **CSP-005** Look for a value rule that lives in the client or in a second place. In the Experience Studio module: a sanitizer, trim, filter, coercion or default applied to a property value before the save, a layout re-derived instead of relayed verbatim after the save, a control that reads or writes storage keys instead of the property key, a picker entity derived from the property type, or a second element type beside `ContentElementNode`. On the server: a copy of an acceptance rule, a default's shape or the nesting bound in diagnostics, the conformance validator, the codec or a mutation operation instead of a call to its one owner. A copied rule diverges, and the module then stores or drops a value depending on the path it takes. Rule: [Every rule about a value is the server's](../../../../src/Core/Framework/ContentSystem/docs/principles/values.md#every-rule-about-a-value-is-the-servers-and-the-client-sends-the-raw-value), [A rule about a stored value has one owner](../../../../src/Core/Framework/ContentSystem/docs/principles/values.md#a-rule-about-a-stored-value-has-one-owner-and-every-path-that-needs-the-rule-calls-that-owner), [Declared type and presentation metadata choose an editor control](../../../../src/Core/Framework/ContentSystem/docs/principles/clients.md#declared-type-and-presentation-metadata-choose-an-editor-control-never-the-reverse). Example: an earlier design kept a private match table for the same admission rule in diagnostics, the conformance validator and the mutation operations, and the three tables disagreed.
- **CSP-006** Look for a default applied at serve time, a present null and an absent key collapsed into one state, an integer-castable map key coerced instead of rejected, or an empty map emitted or stored. Defaults are seeded at write time by `LayoutDefaultSeeder` into absent keys only; a serve-time default (`?? $declaredDefault` in rendering, diagnostics or a Twig component outside the documented prop fallback) makes an unfilled required property look filled and lets a later declaration change what stored layouts render. `isset` where `array_key_exists` is meant reads an authored null as absent. Rule: [The module seeds a property default at write time, never at serve time](../../../../src/Core/Framework/ContentSystem/docs/principles/stored-model.md#the-module-seeds-a-property-default-at-write-time-never-at-serve-time), [A present null and an absent key are different states](../../../../src/Core/Framework/ContentSystem/docs/principles/values.md#a-present-null-and-an-absent-key-are-different-states), [Every map key is a string](../../../../src/Core/Framework/ContentSystem/docs/principles/stored-model.md#every-map-key-is-a-string-and-the-module-rejects-an-integer-castable-key-never-coerces-it), [One encoding per meaning](../../../../src/Core/Framework/ContentSystem/docs/principles/values.md#one-encoding-per-meaning-the-module-stores-an-empty-map-as-absence). Example: `RenderedElementFactory::create()` reads loader values with `array_key_exists` and skips an authored null, so a null in `properties` means a resolution ran and found nothing.
- **CSP-007** Look for a layout write that reaches storage past `LayoutWriteBoundary::apply()` or the `StoredTreeConstraints` descriptor, a new write pass without a stated position in the order, a pass that overwrites a value the author set, or a skip flag that also skips the descriptor. Every route that persists a layout commits through the one boundary, including plain DAL writes, the Sync API, imports and fixtures; only raw SQL and migrations may bypass it, and such a writer must seed required defaults and write the stored shape itself. Rule: [Every layout write passes through the write boundary](../../../../src/Core/Framework/ContentSystem/docs/principles/write-admission.md#every-layout-write-passes-through-the-write-boundary-a-single-choke-point), [The order of the write passes is part of the contract](../../../../src/Core/Framework/ContentSystem/docs/principles/write-admission.md#the-order-of-the-write-passes-is-part-of-the-contract), [No DAL write can bypass the constraint descriptor](../../../../src/Core/Framework/ContentSystem/docs/principles/write-admission.md#no-dal-write-can-bypass-the-constraint-descriptor). Example: `ContentLayoutWriteMemoLifetimeTest` shows that a DAL write under `LayoutGate::SKIP_VALIDATION_STATE` still passes the write boundary.
- **CSP-008** Look for a change to the render path that adds a stage as a listener, orders stages by listener priority, moves an internal stage onto one of the two tree-replacement events, edits the tree a listener received instead of replacing it, derives structure or slots from a property value, lets a template read beyond `id`, `component`, `properties`, `slots` and `style`, stores a request-scoped toggle in the content model, or gives preview a storage or render path of its own. Rendering stages are direct calls handing each other typed immutable results, both modes run the same path, and preview is a second entry into that one path. Rule: [Rendering stages are direct calls](../../../../src/Core/Framework/ContentSystem/docs/principles/rendering.md#rendering-stages-are-direct-calls-handing-each-other-typed-immutable-results), [Structure is a function independent of rendering mode](../../../../src/Core/Framework/ContentSystem/docs/principles/rendering.md#structure-is-a-function-independent-of-rendering-mode), [A template reads a rendered element through a fixed small surface](../../../../src/Core/Framework/ContentSystem/docs/principles/rendering.md#a-template-reads-a-rendered-element-through-a-fixed-small-surface), [Preview is a second entry into the one rendering path](../../../../src/Core/Framework/ContentSystem/docs/principles/preview.md#preview-is-a-second-entry-into-the-one-rendering-path-never-a-second-storage-path), [StoredElement and RenderedElement are two classes](../../../../src/Core/Framework/ContentSystem/docs/principles/stored-model.md#storedelement-and-renderedelement-are-two-classes-joined-by-one-explicit-conversion). Example: the old priority bands of the hydration events never applied in the order they declared, and in-place mutation of one shared element class became an extension contract by accident.
- **CSP-009** Look for a widened extension surface: a class added to `InternalClassRule::CONTENT_SYSTEM_PUBLIC_SURFACE` without a check that the point delivers what it claims, a public member whose signature names a type the list does not name, an app-shipped declaration that is trusted or patched instead of validated and reconciled under the per-app lock, a lifecycle handler without one of the hooks, a member or subscribed service added to `StorefrontController` or another platform base class, or a capability that needs a core edit per entity or per element. Rule: [The extension surface is a deliberate, bounded, listed choice](../../../../src/Core/Framework/ContentSystem/docs/principles/extension-surface.md#the-extension-surface-is-a-deliberate-bounded-listed-choice), [An app-shipped declaration is validated and reconciled](../../../../src/Core/Framework/ContentSystem/docs/principles/extension-surface.md#an-app-shipped-declaration-is-validated-and-reconciled-by-the-module-never-trusted-or-patched), [The module adds nothing to a platform base class plugins extend](../../../../src/Core/Framework/ContentSystem/docs/principles/extension-surface.md#the-module-adds-nothing-to-a-platform-base-class-plugins-extend). Example: `StorefrontController::loadContentPage()` is the documented leftover that the rule now forbids; `ProductContentLayoutDefinition` and `CategoryContentLayoutDefinition` carry per-entity page data until a type-declared mechanism replaces them.
- **CSP-010** Look for a Store API endpoint of the module changed without the matching file under `Framework/Api/ApiDefinition/Generator/Schema/StoreApi/` in the diff, and for a domain service registered in `content-system.php` instead of the DI of its owning module. The README's domain-placement section says which classes are domain-owned. Rule: [AGENTS.md constraints](../../../../src/Core/Framework/ContentSystem/AGENTS.md#constraints), [Domain placement](../../../../src/Core/Framework/ContentSystem/README.md#domain-placement). Example: none recorded yet.

## Do not flag

### CI covers

- PHPStan `InternalClassRule`: every class in a `ContentSystem` namespace is internal unless `CONTENT_SYSTEM_PUBLIC_SURFACE` names it. Report CSP-009 for what the rule does not see: public signatures that name unlisted types, and entries added to the list.
- The pinning tests each principle names under `In code`. When the pinning test is in the diff and green, do not re-derive the rule by hand; check instead that rule, test and code changed together (CSP-002).
- Danger and the standard PHPUnit, Jest and ESLint jobs of the Administration.

### Documented exceptions

Every principle file carries an `Exceptions` paragraph. Read it before flagging: the Storefront may catch the outer render failure, a loader degrades to not-found on a collaborator's HTTP exception, mapping fallbacks and omissions are explicit outcomes, `Sw:Grid:Container` keeps a prop fallback for callers outside stored layouts, the codec and the constraint descriptor keep separate copies of the wiring rules by design, and `StorefrontController::loadContentPage()` stays until separate work removes it.

### Other guides

- Compatibility of a public class, method or event: `bc-php` and `bc-extension-points`, not this guide.
- The shape of a Store API response: `bc-api-contracts`. This guide only asks for the OpenAPI schema file (CSP-010).
- The component API of the Experience Studio module: `bc-admin`. This guide only covers who owns a value rule (CSP-005).

## Severity

- `blocking`: a layout write that reaches storage past the write boundary or the constraint descriptor (CSP-007), or an app-shipped declaration that is trusted unvalidated (CSP-009). Every later render can throw on what such a write stored.
- `major`: a contradiction of a rule, `Why` or `Decided against` line without a change to the principle file (CSP-001), silent degradation (CSP-003), an unreported loss or a code outside the pinned set (CSP-004), a client-owned or duplicated value rule (CSP-005), a serve-time default or a collapsed null (CSP-006), a listener-shaped stage or a second render path (CSP-008), a rule changed without its pinning test (CSP-002).
- `minor`: a missing OpenAPI schema file or a service registered in the wrong DI file (CSP-010), a widened public signature that only needs a list entry (CSP-009).
