## Why this guide exists

The Content System (`src/Core/Framework/ContentSystem/`, `src/Storefront/ContentSystem/`, the domain loaders and mapping providers under `src/Core/*/ContentSystem/`, the app lifecycle under `src/Core/Framework/App/`) and its editor, the Experience Studio module in the Administration, are designed around written principles: one file per area under [docs/principles/](../../../../src/Core/Framework/ContentSystem/docs/principles/README.md#index), each with the rule, a `Why` line, often a `Decided against` line, the exceptions under the heading they belong to, and the code that pins it. The module's [AGENTS.md](../../../../src/Core/Framework/ContentSystem/AGENTS.md#constraints) asks every change to be checked against the principle file of its area. A review that reads only the diff cannot do that check, because the principles live next to the code, not in the coding guidelines. This guide says where to look and what a violation looks like; the principle files are the authoritative text.

## Check

Before the rules:

- Read the principle files at the merge base, `git show <merge-base>:<path>`, never from the PR head. A PR can edit a principle file, and that edit is a subject of CSP-001 and CSP-002, not the yardstick.
- Go from a changed path to its principles through the folder's `AGENTS.md` (every folder under `Framework/ContentSystem/` and `Storefront/ContentSystem/` has one, with the principle headings and concrete `Check:` questions), or through the "By area" and "By task" lists of [docs/principles/README.md](../../../../src/Core/Framework/ContentSystem/docs/principles/README.md#index).
- Read the rule's whole section, including the `Exceptions` paragraph under its heading where there is one. Cite the file and the heading in every finding. Where the principle file and this guide differ, the principle file wins.

- **CSP-001** Look for a change that contradicts a rule, a `Why` line or a `Decided against` line of the principle file of its area and is not covered by the exceptions under that heading. Typical shapes: a first-wins pick or precedence rule that resolves an ambiguous declaration, a malformed registry row that is skipped and logged, a layout polymorphic over root sources, a second client type for the element shape. The principles record decisions that were made once and costs that were reversed; a change that reopens one needs the principle file changed in the same PR, with its `Why` updated. Rule: [AGENTS.md constraints](../../../../src/Core/Framework/ContentSystem/AGENTS.md#constraints), [principles index](../../../../src/Core/Framework/ContentSystem/docs/principles/README.md#index). Example: none recorded yet.
- **CSP-002** Look for the three mechanical checks that `AGENTS.md` asks for. A changed rule in `docs/principles/*.md` whose pinning test (named under `In code`) is not in the diff. A removed or loosened assertion in a pinning test, such as `ContentSystemExceptionTest`, `StoredTreeShapeConformanceTest`, `ContentLayoutDefaultSeedingTest` or `ElementIdRuleTest`, while no principle file changes. A Store API endpoint of the module changed without the matching file under `Framework/Api/ApiDefinition/Generator/Schema/StoreApi/`. A domain service registered in `content-system.php` instead of the DI of its owning module ([Domain placement](../../../../src/Core/Framework/ContentSystem/README.md#domain-placement) lists which classes are domain-owned). A new test case or a renamed test is not a finding. Rule: [AGENTS.md constraints](../../../../src/Core/Framework/ContentSystem/AGENTS.md#constraints). Example: none recorded yet.
- **CSP-003** Look for a component that degrades instead of throwing: a `catch` that returns null, an empty array or a stale value; a raw input value clamped or coerced instead of rejected (`max(1, $size)`, `?? $default` on a value the rule rejects); a value-domain check loosened to make a suite pass; a registry loader that skips a malformed declaration or invents a name for it. A degraded result that looks valid cannot be told from a correct one. The exceptions are named: mapping fallbacks and omissions, the Storefront catching the outer render failure, and the loader degradations of CSP-010. Rule: [A component throws where it meets invalid data, and nothing degrades silently](../../../../src/Core/Framework/ContentSystem/docs/principles/failure-and-loss.md#a-component-throws-where-it-meets-invalid-data-and-nothing-degrades-silently), [A declaration or registration defect fails the container build or the registry load](../../../../src/Core/Framework/ContentSystem/docs/principles/failure-and-loss.md#a-declaration-or-registration-defect-fails-the-container-build-or-the-registry-load-before-any-request-uses-the-declaration). Example: none recorded yet. Reference: `SlicedDistributionConfig` rejects a slice size below 1 instead of clamping it.
- **CSP-004** Look for a loss the response does not report, and for a defect code that bypasses the pinned sets. A mutation that detaches a child must return it as orphaned and name every dropped property and wiring key; a request DTO that accepts extra attributes, or a route that strips an undeclared field instead of answering 400, hides the loss. A new client-defect code enters `CLIENT_DEFECT_CODES`, `ContentSystemExceptionTest` and the documentation in one change; a changed value of an existing code is a break. A new structural code of a mutation operation enters the Administration's `MUTATION_ERROR_SNIPPETS` and `Api/docs/mutation-errors.md` together. For the ux persona: an editor change that discards the orphaned children or the dropped names of the mutation response promotes silent loss. Rule: [The module drops nothing silently and reports every loss](../../../../src/Core/Framework/ContentSystem/docs/principles/failure-and-loss.md#the-module-drops-nothing-silently-and-reports-every-loss), [One exception class holds a closed, pinned set of client-defect codes](../../../../src/Core/Framework/ContentSystem/docs/principles/failure-and-loss.md#one-exception-class-holds-a-closed-pinned-set-of-client-defect-codes). Example: none recorded yet.
- **CSP-005** Look for a value rule that lives in the client or in a second place. In the Experience Studio module: a sanitizer, filter, coercion or default applied to a property value before the save, a layout re-derived instead of relayed verbatim after the save, or a control that reads and writes storage keys instead of the property key. On the server: a copy of an acceptance rule, a default's shape or the nesting bound instead of a call to its one owner. A copied rule diverges, and the module then stores or drops a value depending on the path the value takes. Rule: [Every rule about a value is the server's](../../../../src/Core/Framework/ContentSystem/docs/principles/values.md#every-rule-about-a-value-is-the-servers-and-the-client-sends-the-raw-value), [A rule about a stored value has one owner](../../../../src/Core/Framework/ContentSystem/docs/principles/values.md#a-rule-about-a-stored-value-has-one-owner-and-every-path-that-needs-the-rule-calls-that-owner), [Declared type and presentation metadata choose an editor control](../../../../src/Core/Framework/ContentSystem/docs/principles/clients.md#declared-type-and-presentation-metadata-choose-an-editor-control-never-the-reverse). Example: an earlier design kept a private match table for the same admission rule in diagnostics, the conformance validator and the mutation operations, and the three tables disagreed.
- **CSP-006** Look for a declared default applied at serve time, in rendering, diagnostics or a Twig component outside the documented prop fallback; for a present null and an absent key collapsed into one state, typically `isset` or `??` on a raw property or loader-value map where `array_key_exists` is meant; and for an integer-castable map key coerced instead of rejected. A serve-time default makes an unfilled required property look filled and lets a later declaration change what stored layouts render. Rule: [The module seeds a property default at write time, never at serve time](../../../../src/Core/Framework/ContentSystem/docs/principles/stored-model.md#the-module-seeds-a-property-default-at-write-time-never-at-serve-time), [A present null and an absent key are different states](../../../../src/Core/Framework/ContentSystem/docs/principles/values.md#a-present-null-and-an-absent-key-are-different-states), [Every map key is a string](../../../../src/Core/Framework/ContentSystem/docs/principles/stored-model.md#every-map-key-is-a-string-and-the-module-rejects-an-integer-castable-key-never-coerces-it). Example: none recorded yet. Reference: `RenderedElementFactory::create()` reads loader values with `array_key_exists` and skips an authored null, so a null in `properties` means a resolution ran and found nothing.
- **CSP-007** Look for a layout write that reaches storage past `LayoutWriteBoundary::apply()` or the `StoredTreeConstraints` descriptor, a skip flag that also skips the descriptor, a new write pass without a stated position in the pass order, or a pass that overwrites a value the author set. Every route that persists a layout commits through the one boundary, including plain DAL writes, the Sync API, imports and fixtures; only raw SQL and migrations may bypass it, and such a writer seeds required defaults and writes the stored shape itself. Rule: [Every layout write passes through the write boundary](../../../../src/Core/Framework/ContentSystem/docs/principles/write-admission.md#every-layout-write-passes-through-the-write-boundary-a-single-choke-point), [The order of the write passes is part of the contract](../../../../src/Core/Framework/ContentSystem/docs/principles/write-admission.md#the-order-of-the-write-passes-is-part-of-the-contract), [No DAL write can bypass the constraint descriptor](../../../../src/Core/Framework/ContentSystem/docs/principles/write-admission.md#no-dal-write-can-bypass-the-constraint-descriptor). Example: none recorded yet.
- **CSP-008** Look for a render stage added as a listener or ordered by listener priority, a listener that edits the tree it received instead of replacing it through its event, a template that reads a rendered element beyond `id`, `component`, `properties`, `slots` and `style` or stores a request-scoped toggle in the content model, and a preview that gets a storage or render path of its own. Rendering stages are direct calls handing each other typed immutable results, both modes run the same path, and preview is a second entry into that one path. Rule: [Rendering stages are direct calls](../../../../src/Core/Framework/ContentSystem/docs/principles/rendering.md#rendering-stages-are-direct-calls-handing-each-other-typed-immutable-results), [A template reads a rendered element through a fixed small surface](../../../../src/Core/Framework/ContentSystem/docs/principles/rendering.md#a-template-reads-a-rendered-element-through-a-fixed-small-surface), [Preview is a second entry into the one rendering path](../../../../src/Core/Framework/ContentSystem/docs/principles/preview.md#preview-is-a-second-entry-into-the-one-rendering-path-never-a-second-storage-path), [StoredElement and RenderedElement are two classes](../../../../src/Core/Framework/ContentSystem/docs/principles/stored-model.md#storedelement-and-renderedelement-are-two-classes-joined-by-one-explicit-conversion). Example: the priority bands of the old hydration events never applied in the order they declared, and in-place mutation of one shared element class became an extension contract by accident.
- **CSP-009** Look for a class added to `InternalClassRule::CONTENT_SYSTEM_PUBLIC_SURFACE` without a check that the point delivers what it claims, a public member of a listed class whose signature names a type the list does not name, an app-shipped declaration that is trusted or patched instead of validated and reconciled under the per-app lock, a lifecycle handler without one of the hooks, and a member or subscribed service added to `StorefrontController` or another platform base class. Rule: [The extension surface is a deliberate, bounded, listed choice](../../../../src/Core/Framework/ContentSystem/docs/principles/extension-surface.md#the-extension-surface-is-a-deliberate-bounded-listed-choice), [An app-shipped declaration is validated and reconciled](../../../../src/Core/Framework/ContentSystem/docs/principles/extension-surface.md#an-app-shipped-declaration-is-validated-and-reconciled-by-the-module-never-trusted-or-patched), [The module adds nothing to a platform base class plugins extend](../../../../src/Core/Framework/ContentSystem/docs/principles/extension-surface.md#the-module-adds-nothing-to-a-platform-base-class-plugins-extend). Example: `StorefrontController::loadContentPage()` is the documented leftover that the rule now forbids.
- **CSP-010** Look for a data loader that degrades on anything but a named domain outcome, for example a `catch (\Throwable)` or a `catch (\Exception)` around the load instead of the collaborator's HTTP exception; a loader that reads a request parameter to decide what it loads; a loader that reads its inputs from anything but the typed inputs resolved from its own declared specification; and an element that gets a sales-channel context value from anything but a loader that returns that value. A loader that swallows a driver failure or a type error serves a page that looks complete. Rule: [A loader degrades on a named domain outcome and lets every other fault propagate](../../../../src/Core/Framework/ContentSystem/docs/principles/data-loading.md#a-loader-degrades-on-a-named-domain-outcome-and-lets-every-other-fault-propagate), [No request selects what a loader loads](../../../../src/Core/Framework/ContentSystem/docs/principles/data-loading.md#no-request-selects-what-a-loader-loads), [A loader consumes typed inputs resolved from its own declared specification](../../../../src/Core/Framework/ContentSystem/docs/principles/data-loading.md#a-loader-consumes-typed-inputs-resolved-from-its-own-declared-specification). Example: none recorded yet. Reference: `BreadcrumbDataLoader::load()` catches `ShopwareHttpException` only and lets a `\TypeError` or a driver failure propagate.

## Do not flag

### CI covers

- PHPStan `InternalClassRule`: every class in a `ContentSystem` namespace is internal unless `CONTENT_SYSTEM_PUBLIC_SURFACE` names it, with the test stubs under `src/Core/Test/Stub/` exempt. Report CSP-009 for what the rule does not see: public signatures that name unlisted types, and entries added to the list.
- The pinning tests each principle names under `In code`, when they are unchanged and CI is green. Then the rule holds; check only a changed pinning test (CSP-002).
- Danger and the standard PHPUnit, Jest and ESLint jobs of the Administration.

### Legitimate patterns

- The exceptions under a rule's heading. Among them: the Storefront may catch the outer render failure; a loader degrades to not-found on a collaborator's HTTP exception or on an id that `Uuid::isValid()` rejects; mapping fallbacks and omissions are explicit outcomes; the multi-entity picker trims unresolvable ids; `Sw:Grid:Container` keeps a prop fallback for callers outside stored layouts; the module emits an empty `properties` map and the `slots` of a skeleton or decomposed node; `ProductVariantSelectionSubscriber` enriches variant options during finalization as domain postprocessing; the codec and the constraint descriptor keep separate copies of the wiring rules by design; `StorefrontController::loadContentPage()` stays until separate work removes it.
- `(string)` on a map key and `isset` on a map of `StoredValue` objects, as `RenderedElementFactory` does: the ban of CSP-003 and CSP-006 is on raw property values.
- Compatibility of a public class, method or event: `bc-php` and `bc-extension-points`, not this guide.
- The shape of a Store API response: `bc-api-contracts`. This guide only asks for the OpenAPI schema file (CSP-002).
- The component API of the Experience Studio module: `bc-admin`. This guide only covers who owns a value rule (CSP-005).

## Severity

- `blocking`: a layout write that reaches storage past the write boundary or the constraint descriptor (CSP-007), because every later render can throw on what it stored; an app-shipped declaration trusted unvalidated (CSP-009), because one malformed row then fails every load of its registry.
- `major`: a contradiction of a rule, `Why` or `Decided against` line without a change to the principle file (CSP-001); a loosened pinning assertion (CSP-002); silent degradation (CSP-003, CSP-010); an unreported loss or a code outside the pinned sets (CSP-004); a client-owned or duplicated value rule (CSP-005); a serve-time default or a collapsed null (CSP-006); a new write pass without a stated position or a pass that overwrites an authored value (CSP-007); a listener-shaped stage, an in-place tree edit or a second render path (CSP-008); a missing lifecycle hook or a new member on a platform base class (CSP-009).
- `minor`: a missing OpenAPI schema file or a service in the wrong DI file (CSP-002); a public signature that only needs a list entry (CSP-009).
