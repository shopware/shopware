## Your vision should shape your software. Not the other way around.

A distinctive brand needs more than a familiar checkout. It needs room to tell its story, express its personality, and turn a good idea into an experience customers remember.

Shopware gives you a complete commerce foundation **and the source code to make it your own**. Start with a working storefront, catalog, cart, checkout, and administration. Then build the product advisor, configurator, integration, or buying journey your business calls for.

| Why Shopware | What that means for your project |
| :--- | :--- |
| **Make the experience unmistakably yours** | Combine Shopping Experiences, custom themes, or an API-driven frontend. |
| **Build on a complete foundation** | Focus on what makes your business different rather than rebuilding commerce basics. |
| **Keep control of your next move** | Extend the MIT-licensed core, choose compatible hosting, and decide how external services use your data. |
| **Build with your preferred coding agent** | Let agents inspect code and propose changes while you review, test, and deploy them. |

## Choose your starting point

Different projects need different first steps. Pick the path that fits what you want to do.

| I want to… | Start here | What to expect |
| :--- | :--- | :--- |
| **Explore Shopware** | [Create a demo store](https://hub.shopware.com/build) | Try a hosted shop without local installation. The demo has limitations. |
| **Build my own shop** | [Run Shopware locally](#run-shopware-locally) | Create a development project with the Shopware CLI and Docker. |
| **Build an extension or theme** | [Explore extension guides](https://developer.shopware.com/docs/guides/plugins/) | Choose between apps, plugins, themes, and API-based frontends. Scaffold a plugin or theme with `shopware-cli extension create`, then add example features with `shopware-cli extension add`. |
| **Contribute to Shopware core** | [Read the contribution guide](https://github.com/shopware/shopware/blob/trunk/CONTRIBUTING.md) | Follow the upstream contribution workflow, which differs from a merchant project. |

**Curious about an experimental alternative?** A [community browser playground](https://agentic-commerce-lab.github.io/shopware-claude-commerce/) runs a Shopware demonstration using WebAssembly. It is a separate experiment, not the official hosted demo or production hosting. Optional agent features may require your own API key and provider charges.

## Why developers choose Shopware

**Own your stack. No vendor lock-in.** The MIT-licensed core runs wherever you choose to host it, and your code, data, and extensions stay yours. Development happens in the open on GitHub, so you can follow every change, see where the platform is heading, and contribute your own solutions back.

Under the hood, Shopware is a Symfony application with a Vue.js administration, a Twig storefront, and APIs and extension points throughout the platform.

| Part | Technology |
| :--- | :--- |
| Backend | PHP, Symfony, Doctrine DBAL |
| Storefront | Twig, Bootstrap |
| Administration | Vue, TypeScript |
| Data | MySQL or MariaDB; Shopware Data Abstraction Layer |
| Integrations | Store API and Admin API |

Exact supported versions depend on the Shopware release. See the [installation requirements](https://developer.shopware.com/docs/guides/installation/requirements.html).

Shopware supports different extension models:

| Approach | Use it for | Deployment note |
| :--- | :--- | :--- |
| **Theme** | Change storefront presentation and templates | Supported implementation differs by hosting model. |
| **App** | Integrate external services using APIs and webhooks | Runs outside the Shopware core. |
| **Plugin** | Add in-process PHP/Symfony behavior | Requires a compatible self-hosted deployment. |
| **Headless frontend** | Build a custom shopping experience with the Store API | Uses the shop's sales-channel APIs. |

[Compare extension options](https://developer.shopware.com/docs/guides/plugins/) · [Explore Shopware Frontends](https://frontends.shopware.com/)

## Run Shopware locally

We recommend the [Shopware CLI](https://developer.shopware.com/docs/products/tools/cli/) to create, develop, build, and validate your Shopware projects and extensions, with plenty more built-in features. Its interactive dashboard shows credentials, health checks, live logs, and more. The recommended Docker setup adds a production-like environment and lets you run several Shopware versions side by side, each on its own local HTTPS hostname.

**[Start Shopware in minutes →](https://developer.shopware.com/)** Install the Shopware CLI, create a project, and open your shop, with step-by-step instructions. The [installation guide](https://developer.shopware.com/docs/guides/installation/) provides more details. This setup is for local development. Ready to go live? See the [hosting guide](https://developer.shopware.com/docs/guides/hosting/).

Can't use Docker? Choose PHP and Composer when creating your project, and the Shopware CLI still handles the installation.

## Extend Shopware your way

Choose the extension point that fits your project. For example, a storefront theme or plugin can override a Twig block without replacing the entire template:

```twig
{% sw_extends '@Storefront/storefront/component/buy-widget/buy-widget.html.twig' %}

{% block buy_widget_price %}
    {{ parent() }}
    <p class="delivery-note">Ships within 24 hours</p>
{% endblock %}
```

This is an illustrative snippet; follow the [theme guides](https://developer.shopware.com/docs/guides/plugins/themes/) for a complete implementation. For integrations, use the [Admin API](https://developer.shopware.com/docs/guides/integrations-api/) or [Store API](https://developer.shopware.com/docs/guides/integrations-api/), depending on the task.

## Build with your preferred coding agent

Open source makes implementation details available to both developers and their tools. Coding agents can read project code, [agent instructions](https://github.com/shopware/shopware/blob/trunk/AGENTS.md), and [development skills](https://github.com/shopware/shopware/tree/trunk/.agents/skills) to help create and test extensions.

The [Shopware CLI](https://developer.shopware.com/docs/products/tools/cli/) helps you discover Shopware AI tooling: run `shopware-cli ai list` to see the available agent skills and MCP servers, and `shopware-cli ai add` to install one into your coding agent. More integrations are on the way.

A useful first task:

```text
Read the project's agent instructions and identify the Shopware version.
Help me build a small plugin for a gift-message feature.
First explain the supported extension points and the data flow.
Do not edit vendor files or core source. Propose a minimal implementation,
include a meaningful test, and show me how to disable the plugin again.
```

Review and test generated changes before deployment. A **coding agent** working with project files is different from an **administrative agent** connected to a running shop. Learn about the [Shopware MCP server](https://developer.shopware.com/docs/products/tools/mcp-server/) and the separate [Agentic Commerce project](https://github.com/shopware/agentic-commerce); access depends on configuration and permissions.

## Open source, with clear choices

The [Shopware core is MIT-licensed](https://github.com/shopware/shopware/blob/trunk/LICENSE). You can inspect, modify, and self-host it under that license. Hosting, commercial plans, Shopware Account and Store services, extensions, and external AI or payment providers may have separate terms and costs. Review the [Community Edition Fair Usage Policy](https://www.shopware.com/en/news/fair-usage-policy-community-edition/) and [current plans](https://www.shopware.com/en/pricing/) when choosing a deployment model.
