# Administration
* Added `composer admin:setup-extension-tooling` — discovers every installed extension with Administration sources (from `var/plugins.json`, with a `bundle:dump` hint when that file is older than `custom/plugins/`) and generates disposable, marker-owned tooling state: one tsconfig per extension under `var/admin-extension-tooling/`, a solution-style root `tsconfig.json`, a scoped root `eslint.config.mjs`, IDE bootstraps for VS Code and Zed (PhpStorm setup is printed), and a marker-fenced ignore block for the generated root files in the project `.gitignore` (skipped when already covered; `--no-gitignore` opts out permanently). The report classifies extensions as ready / bridged / bridge-unwired / custom, lists changed files by path, and prints only the actually-missing next step per extension. Optional `--shim=<name>` writes a self-ignoring `.shopware-admin/` bridge (holding the machine-specific paths, merging aliases from a committed `tsconfig.aliases.json`) and, for a plugin with no config yet, two small committable `tsconfig.json` / `eslint.config.mjs` (spec files excluded by default) that just extend it — never overwritten; `--check` validates without writing (exit 1 on drift); `--explain` prints the full discovered state including every managed file.
* Added `composer admin:check-extensions` — type-checks (vue-tsc) and lints (ESLint) installed Administration extensions with the Administration's own pinned toolchain and readable, colorized output. In an interactive terminal it opens a picker (numbers, ranges, `a`=all, `w`=writable only); pass `--only=<name[,name]>` or `--all` to skip the prompt, and non-interactive shells check all. Extension configs that do not compose the Shopware preset are visibly skipped with a reason-specific `why:` (files-override, missing extends chain, config error) and a `fix:` naming the exact edit — never silently green. TypeScript runs are blocked with the fix command while the entity schema is missing, JavaScript-only extensions report an honest qualified pass instead of a vacuous green, and tool paths render project-relative. `--fix` forwards ESLint autofixes (vendor extensions only when named via `--only`), `--show-commands` prints the underlying tool invocations, `--verbose` shows output for passing/skipped extensions, and findings in `vendor/` extensions report non-fatally unless `--strict-vendor` is set.
* Both commands parse arguments strictly: `-- --help` prints a generated reference, unknown or misspelled flags abort with exit 2 and a did-you-mean suggestion before anything is written (options placed before Composer's `--` separator never reach the command).
* Added `src/Administration/Resources/app/administration/extension-tooling/` — the committed contract: `tsconfig.base.json` (strict preset), `admin-types.d.ts` (the live type surface: `global.types.ts` + generated entity schema + html shim), `eslint.mjs` (parameterized flat-config factory `shopwareAdminExtension()`, including a spec-file block that lints tests without type-aware rules), `legacy-twig.mjs` (Twig template lint preset), and `host-modules.json` (bare modules the host runtime provides; currently `vue`).
* Added `vue-tsc` as an Administration devDependency.
* Both commands are strictly opt-in: no default build, watch, init, or CI flow invokes them.
