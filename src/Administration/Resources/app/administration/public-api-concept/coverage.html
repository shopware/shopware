How a change is classified

The break check asks these questions in order for every element that differs between base and head, in each flag state. The first yes decides the group.

1Is the element, or the unit it belongs to, @private?yes → private never blocks
no ↓
2Was it removed, and did it carry @deprecated tag:vX that the head version has reached?yes → allowed
no ↓
3Does the PR add a matching entry to accepted-breaks.json?yes → accepted never blocks
no ↓
4Was it removed, renamed, moved or changed incompatibly, or did a block lose its v-if context or a scope variable?yes → break fails CI
no ↓
5Is it new?yes → addition
no ↓
6Is it a new deprecation, a wider type, a renamed parameter or a resolved crossing?yes → info
no → no finding (for example code inside a method)
