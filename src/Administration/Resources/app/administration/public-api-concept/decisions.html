Decisions

What we decided so far and why. Refer to D and S numbers in your feedback.

Decision 12 was a working agreement for the branch, not a design decision, and is left out.

What is public

IDDecisionWhy
D1Everything without @private is public.The rule is already documented. Requiring @public instead would make almost everything private, because only about 50 items carry it.
D2Private parts are in the same files, marked, and never a break.Reviewers still see private changes, without a second set of files.
D13@private on a component or mixin export makes the whole unit private, including its name and blocks.This is how authors use the export tag today.

Scope

IDDecisionWhy
D3Reviewers and plugins are equally important.The snapshot has to produce readable diffs and a usable type contract from the start.
D4The Shopware object, components, blocks, routes, snippets, position identifiers and data sets.Plugins use all of them as strings.
D9The whole Administration.A partial snapshot gives false safety.
D16Referenced source types get their own copy.Otherwise a change to a shared type would be invisible.
D17Native setup SFCs from the start.They are coming, and adding them later costs more.
D19Snippet keys with placeholders and plural forms, never texts.A renamed placeholder breaks plugin $t calls; texts change too often to track.

Format

IDDecisionWhy
D5.d.ts files plus an .api.md report.TypeScript can check the .d.ts files; the report gives readable diffs. JSON alone could do neither well.
D6Two flag states, current and major, both committed and compared.Breaks behind the major flag (#17339) are invisible in a single snapshot.
D15Keep index.json as a machine index.Vite, Jest and ESLint need a cheap lookup without loading TypeScript.
D22The report is an outline without tree characters; the check adds a grouped summary and annotations.Tree characters change on every move and make diffs noisy.
D25Components record template refs and static CSS classes. A missing or retargeted ref is a break, a missing class is info.635 store plugins read core $refs, 1,541 style core classes; classes change too often to block on.
D23Flag state markers name the version: [until v6.8.0] and [from v6.8.0].[current only] loses its meaning in an old commit, a version does not.

CI and review

IDDecisionWhy
D7A drift check and a break check that runs the target branch's generator on base and head.Regenerating the snapshot or changing the generator cannot hide a break.
D11A simple HTML page per check run, without simulating plugin overrides.A simulation would be costly and still incomplete.
D14Intended breaks go into accepted-breaks.json with a justification, approved by code owners.A PR label leaves no reason and no review trail.
D36Finding texts never suggest accepted-breaks.json. Entries name the pattern that would apply, why it cannot be followed, and an issue. Coding agents never add entries on their own.Developers and agents take the easy way out when the check offers it on every finding.
D18Elements that already cross blocks on trunk are the baseline.Otherwise every PR would fail on old crossings.

Plugins and existing tools

IDDecisionWhy
D8The snapshot ships in the Administration package and is used by admin-types.d.ts and admin:check-extensions.Plugins already use both.
D10Replace the four generated lists directly.Two sources of truth would drift apart.
D20Core types Component.override as an interface; the snapshot adds a typed signature.Plugins keep their code; a cast or a new function would force changes everywhere.
D21A helper wrapOverrideConfig for override files loaded lazily.Most large plugins load overrides lazily.
D26Filters, directives, ACL privileges, settings groups, CMS, rule conditions, search types, flow actions and custom field types that core registers are units.Hundreds of store plugins use these names; a removal breaks them silently.
D27Event bus events and feature flags are units. A missing event is a break, a missing flag is info.Plugins listen to core events and branch on core flags.
D28SCSS variables and mixins are units. A missing name is a break, a changed value is info.691 store plugins import ~scss/variables; a missing variable fails the plugin build.
D29admin:check-extensions checks the new names and warns about $parent and imports from src/.These uses cannot be typed, but plugin developers should know the risk.
D30A store usage index annotates findings and detects name collisions (proposal).Counts make findings concrete and measure false alarms.
D24Blocks record their context: whether they follow an open v-if chain, and which v-for and slot variables they can use. v-if chains across blocks count as crossings.Plugin templates continue core v-if chains and use loop and slot variables; #20959 removed itemIndex from a slot.

Upgrade path for plugins

IDDecisionWhy
D31@deprecated is for removals and replacements, with {@link} to the replacement. A planned change to an element that stays uses @bc-change <Kind>, named after the PHP BCChange attributes where they fit.The extension lint reports every @deprecated use as an error, so planned changes in @deprecated would flag plugins that have nothing to migrate yet. PHP dropped its reason:* markers for the same reason.
D32Method parameters and emit arguments get element ids and findings of their own. Removing a parameter is a break unless announced with ParameterRemoval.#20959 removed itemIndex, and overrides that read it got undefined.
D33One change pattern per kind of change. Findings name their pattern, and pattern_incomplete reports a marker without its counterpart.Without fixed patterns every PR invents its own way, and some ways break plugins on the current version.
D34admin:check-extensions --target=<major> reports every plugin use the next major breaks, as actionable now or at upgrade, in text, JSON or SARIF.Plugin developers can answer "how much work is the upgrade?" before they update, and hand the list to an agent.
D35A plugin is ready when nothing is reported against both states. Patterns that allow one change for both versions get a codemod.Plugins can adapt once on the current version and keep working after the update.
D37Marker validation in three layers, implemented for the Administration separately from PHP: format and attachment in the generator and an ESLint rule, references and patterns in the break check.A typo in a marker would otherwise stay a plain comment and surface as an unannounced break at the major.

Assumptions

We assumed these without asking. Correct them if they are wrong.

IDAssumption
S1Only the core Administration is generated. The Storefront bundle's Administration extension and installed plugins serve as real consumers when we verify the generator.
S2A removal in the major that a @deprecated tag:vX announced is not a break. Only tags in the source count, not entries in UPGRADE-*.md.
S3The folder layout and the split into one unit per component or module are proposed together with the golden files.

Prior art

ToolWhat we took from it

GraphQL InspectorGrouping changes into breaking, dangerous and safe, which became our finding groups.
Go api/*.txtOne line per API element, so diffs stay line-based.
roave/backward-compatibility-checkThe PHP side already compares base and head this way.
