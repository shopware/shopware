Generator

The agreed workflow for generating and checking the snapshot, and a proposed design for the generator, which does not exist yet.

The generator does not exist yet. The workflow follows D7, D10 and D15. The design further down is a proposal.

Workflow

Generating locally

# inside the Docker container, like the existing list generators
composer admin:generate-public-api
  • Writes everything below public-api/ except the hand-written files: FORMAT.md, .gitattributes, _base/ and accepted-breaks.json.
  • Covers the whole core Administration and both flag states in one run.
  • The author commits the result together with the code change.
  • Replaces the four existing list generators. Their consumers (the Vite plugin for shopware:* modules, the Jest setup, an ESLint rule and the successor of meta.spec.js) read index.json.

CI: drift check

Makes sure the committed snapshot matches the code.

  1. Regenerate the snapshot. Fail when git diff is not empty.
  2. Type-check current.d.ts and major.d.ts. This runs the shape and reference checks in the entry points.
  3. Fail only on errors in files below public-api/. The same program also reports errors in node_modules and in local declaration files, which the snapshot does not control.

CI: break check

Decides whether the PR breaks the API.

  1. Run the generator of the target branch on the base commit and on the head commit. Using the target branch's generator, not the PR's, means a PR cannot change the generator to hide its own break. The check never reads the committed snapshot, so regenerating it cannot hide a break either.
  2. Compare base and head per flag state and classify every difference, see the decision tree on the Coverage page.
  3. Apply the entries that the PR added to accepted-breaks.json.
  4. Print the summary, add the annotations and write the HTML page. The job fails when a break is not accepted.

Model and printers

  • The break check compares models, not files, so the output format can change without changing the classification.
  • Three printers write the reports, the .d.ts files and index.json from the same model.
  • A unit gets a .major.d.ts only when its major state differs.

Break check

  • Check out base and head in separate worktrees and run the generator on both.
  • Match elements by their element id, for example component:sw-order-detail/method:onSave, never by file path.
  • Classify, detect renames, then apply accepted-breaks.json. Only entries the PR adds count.

Testing

The generator is built against the 22 fixtures and the 4 historical cases. The done criteria are on the Backtest page.
