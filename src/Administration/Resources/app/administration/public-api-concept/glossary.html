Glossary

The terms these pages use, each with one meaning.

Terms

Snapshot
Everything the generator writes below public-api/: one report and one .d.ts file per unit, plus entry points and index.json.
Unit
One source item with its own snapshot files: a component, a module with its routes, a mixin, a snippet file, a service or a store.
Report (.api.md)
The readable outline of a unit for reviewers. Shows both flag states in one file.
.d.ts file
The TypeScript version of a unit. Plugins compile against it; there is one per flag state.
Flag state: current and major
Current: the major feature flag v6.8.0.0 is off, as in today's releases. Major: the flag is on, as in the next major release. The snapshot is generated for both. Reports mark items of one state with [until v6.8.0] or [from v6.8.0].
Golden files
Hand-written expected output that the generator must reproduce: the example snapshot, the test fixtures and the historical cases.
Example snapshot
The hand-written part of the snapshot on the branch: sw-sales-channel, sw-order, two mixins, the Shopware object, a service, a store, the shopware:* modules and referenced types.
Test fixture
A minimal source tree before and after one kind of change, with the expected snapshot and findings.
Historical case
A real PR replayed on its real commits, with the expected findings. Used as backtest.
Base and head
The commit a PR starts from, and the last commit of the PR.
Drift check
CI check that the committed snapshot matches the code.
Break check
CI check that compares base and head and fails on breaks that are not announced or accepted.
Finding
One classified difference between base and head, for example block_missing. Each finding has a group: break, addition, allowed, accepted, private or info.
Element id
The stable name of an API element in findings and in accepted-breaks.json, for example component:sw-order-detail/method:onSave.
Accepted break
A break the PR makes on purpose, listed with a justification in accepted-breaks.json.
Block
A Twig {% block %} or a native <sw-block>. Plugins override blocks by name.
Extend child
A component created with Component.extend. It inherits the blocks and members of its parent.
Crossing
An HTML element that opens in one block and closes in another, or a v-if chain that continues in another block. Overriding the first block without {% parent %} breaks the markup or the chain.
Registry
A service that collects named entries, such as CMS blocks or rule conditions. The snapshot records the entries core registers, not those of plugins.
Store usage index
Proposal: counts per element id of how many store plugins use it, generated from the internal store plugin mirror. Annotates findings and detects name collisions.
Block context
Two facts about the place of a block that overrides depend on: whether it follows an open v-if chain ([after v-if]), and which v-for and slot variables it can use ([scope: …]).
$super target
A method or computed property that an override can call with this.$super('name').
Position identifier, data set
Extension points of the Meteor Admin SDK in core templates.
Native SFC
A component written as .vue file with <script setup> instead of the Options API.
Referenced type
A TypeScript type from src/ that a unit uses, copied into the snapshot so that changes to it show up.
