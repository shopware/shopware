How to read a report

MarkerMeaning
[until v6.8.0] [from v6.8.0]Exists in one flag state only: in every release before 6.8.0, or from 6.8.0 on
[after v-if]The block follows an open v-if chain, so an override may start with v-else-if or v-else
[scope: index, item]Template variables from an enclosing v-for or slot that an override can use
[deprecated tag:vX] [experimental]Tags from the source; the full message is in the .d.ts file
[private]Not public API; on every line of a private unit
[inherited] [replaced] [keepsParent]Where a block of an extend child comes from: unchanged from the parent, redeclared without {% parent %}, or redeclared with it
[empty] [repeated]Block without content, block declared more than once

Under notes a report lists facts that never fail the check: flag-removal-undeprecated (removed in major without a tag), visibility-conflict, duplicate-snippet-key and dynamic-block. A report never contains counts or "used by" lists, because those change for reasons outside the unit.

Folder layout

The snapshot lives in src/Administration/Resources/app/administration/public-api/ and mirrors src/. Each unit (a component, module, mixin, snippet file, service or store) has an .api.md report and a .d.ts file at the path of its source.

PathContent
module/<dir>/<path>/<name>.*One unit per component of a module
module/<dir>/module.*The module and all its named routes
module/<dir>/snippet.*Snippet keys of the module's en.json
app/component/<path>/<name>.*Global components
app/mixin/<name>.*, app/store/<file>.*Mixins and Pinia stores
core/shopware.*, core/service/<file>.*, core/virtual-modules.*The Shopware object, services, shopware:* modules
types/<path>.*Source types that other units reference (D16)
<name>.major.d.tsOnly when the major state of a unit differs
accepted-breaks.jsonIntended breaks, written by hand (D14)
FORMAT.md, _base/, current.d.ts, major.d.ts, index.jsonSpec, base types, entry points and machine index, see "Internal files"

Internal files

Needed by tools, not by reviewers.

Entry points: current.d.ts and major.d.ts

Each references all files of its flag state and ends with checks that tsc evaluates. Conforms fails when an entry does not have the expected shape. CheckReferences fails when an extends, mixin, route component, parent or redirect names something that does not exist.

current.d.ts
// Generated by `composer admin:generate-public-api`. Do not edit.
// Entry point of the current flag state (v6.8.0.0 off). Every snapshot file, sorted by path.

/// <reference path="./_base/admin-api.d.ts" />
/// <reference path="./app/mixin/notification.d.ts" />
/// <reference path="./module/sw-sales-channel/page/sw-sales-channel-detail.d.ts" />
/// ...

declare namespace AdminApi {
    type _CheckComponents = Conforms<Components, ComponentShape>;
    type _CheckNativeComponents = NativeConforms<Components>;
    type _CheckOverrides = Conforms<ComponentOverrides, ComponentOverrideShape>;
    type _CheckMixins = Conforms<Mixins, MixinShape>;
    type _CheckModules = Conforms<Modules, ModuleShape>;
    type _CheckRoutes = Conforms<Routes, RouteShape>;
    type _CheckSnippets = Conforms<SnippetKeys, Snippet<string, 1 | 2 | 3 | 'array'>>;
    type _CheckReferences = CheckReferences<Components, Routes>;
}

Determinism rules
  • Keys and lines are sorted by codepoint, sections come in a fixed order.
  • Committed files contain no timestamps, versions, absolute paths or line numbers.
  • Two runs on the same commit produce byte-identical output.
  • The generator copies types from the source text and never prints them from the type checker. JS members become AdminApi.Untyped.
