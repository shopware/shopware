# Api

Admin API controllers for the content system. Store API rendering lives in `SalesChannel/`; this directory holds Admin-scoped (`ApiRouteScope`) endpoints: layout preview, resolve-and-diagnose, the nine stateless draft mutation actions, and the nine persisted mutation actions that commit one edit to a stored layout.

## Key Classes

- `ContentPreviewController` - One action, binding `ContentPreviewRequest` via `#[MapRequestPayload]` and delegating the orchestration to `ContentPreviewPageBuilder`. `POST /api/_action/content-system/preview/entity/url` builds the draft, discards the resulting page, and stores the envelope via `ContentPreviewPayloadStore` before returning a Storefront preview URL — a draft the build gate refuses is a 400 and never becomes a token, at one full build per mint. The draft goes through `DraftLayoutDecoder`, which runs a structural gate over the roots and then decodes each surviving one through the same `Layout/Codec/StoredElementCodec` the storage column uses, so a malformed structural container — a scalar `slots`, `dataRequirements`, context map, `style` or attribution map — is refused rather than emptied, and so is nesting past the codec's depth bound. The action neither persists nor caches; checking a draft without minting a token is what the diagnose action is for.
- `ContentPreviewPageBuilder` - The shared orchestration behind both preview paths (admin `ContentPreviewController` and the Storefront `frontend.content-system.preview` render route). `build(ContentPreviewRequest, Context)` synthesizes the sales-channel context, resolves the assignment-free `RenderingSpecification`, decodes and checks the draft layout, runs `ContentPipeline` in `RenderingMode::FULL` without value-index collection, and returns `['result' => RenderResult, 'salesChannelContext' => SalesChannelContext]`.
- `ContentPreviewPayloadStore` - Holds a serialized `ContentPreviewRequest` envelope under a 32-character token in the application cache for five minutes (`expiresAfter(300)`), never in the database. `store()` mints the token (or throws `ContentSystemException::previewPayloadStoreFailed`, 500, if the cache write is rejected); `load()` returns the payload, `null` once the token addresses no entry, or throws `previewPayloadInvalid` (500) on a hit that is not exactly what `ContentPreviewRequest` declares (field set and constraints alike) — a server fault rather than a client one, because the store writes only validated envelopes and the mint action rejects everything the envelope cannot carry.
- `ContentPreviewRequest` - envelope DTO bound via `#[MapRequestPayload]` on the controller action parameter: required `layout` (raw array), `entityType`, `entityId`, `salesChannelId`; optional `languageId`, `currencyId`, `domainId`, `customerId`, `queryParameters`. The `layout` stays raw so `DraftLayoutDecoder` remains the single decode path.
- `ContentDiagnoseController` - Single `POST /api/_action/content-system/layout/diagnose` action. Decodes the draft layout from the request via `DraftLayoutDecoder` (lenient mode — element config defects surface as `invalid_config` diagnostics rather than failing the request); it never reads or writes the stored `content_layout` entity — optionally binds the request `rootSource`'s root context (via `Adapter/RootSourceRegistry::resolveGated()`), runs `Diagnostics/LayoutDiagnostics`, and returns a `DiagnoseResponse` (`{ resolutions, diagnostics }`) — per-element property resolutions and a well-formedness/resolvability report. No persistence, no rendering.
- `ContentDiagnoseRequest` - envelope DTO bound via `#[MapRequestPayload]` on the controller action parameter: optional `layout` (raw array, defaults to an empty tree), optional `rootSource`. Without `rootSource`, only intrinsic well-formedness is evaluated.
- `DraftLayoutDecoder` - Shared draft-layout decode (structural pre-decode gate plus `Layout/Codec/StoredElementCodec::decode()`) used by the preview, diagnose, and mutation routes. `decode()` is strict (a malformed or config-defective element is a 400 `invalidLayoutStructure`); `decodeLintable()` is lenient (config defects become `invalid_config` violations, the rest of the tree survives) for the diagnose route.
- `LayoutMutationController` - Nine `POST /api/_action/content-system/layout/{insert,remove,move,replace,duplicate}-element`, `.../wrap-elements`, `.../unwrap-element`, `.../attach-element`, `.../bind-element` actions. Each binds its request DTO, decodes the draft layout via `DraftLayoutDecoder`, builds one `Mutation/` operation, and runs it through `Mutation/MutationPipeline`, returning the re-resolved layout plus a diagnostics report as a `MutationResponse`. No persistence. The optional `rootSource` binds its root context (via `Adapter/RootSourceRegistry::resolveGated()`) for binding-scope resolvability. `bind-element` applies a registered `Binding/Specification/BindingSpecification`'s wiring onto an element, sourced from the injected `Binding/Registry/AbstractContentSystemBindingSpecificationRegistry`.
- `ContentLayoutMutationController` - The persisted counterpart: nine `POST /api/_action/content-system/layout/{layoutId}/{insert,remove,move,replace,duplicate}-element`, `.../wrap-elements`, `.../unwrap-element`, `.../attach-element`, `.../bind-element` actions. Each binds its request DTO, builds one `Mutation/` operation, and runs it through `Mutation/PersistedLayoutMutator`, which loads the stored layout by id, guards the `expectedVersion` token, applies the operation, and commits the mutated tree through the resolvability gates. The response binding-scope diagnostics come from the loaded layout's single `root_source`, not a request hint.
- Draft mutation request DTOs - One per action (`InsertElementRequest`, `RemoveElementRequest`, `MoveElementRequest`, `ReplaceElementRequest`, `DuplicateElementRequest`, `WrapElementsRequest`, `UnwrapElementRequest`, `AttachElementRequest`, `BindElementRequest`), each bound via `#[MapRequestPayload]` on the controller action parameter. Each carries the raw `layout` (decoded through `DraftLayoutDecoder`) plus the operation's parameters and the optional `rootSource`. `AttachElementRequest` also carries the raw `element` subtree to splice in; `BindElementRequest` carries `elementId` plus the source-qualified `bindingSpecificationId` to apply. `InsertElementRequest` additionally carries an optional `bindingSpecificationId` to apply a specification onto the inserted element atomically.
- Persisted mutation request DTOs - One per action (`ContentLayoutInsertRequest`, `ContentLayoutRemoveRequest`, `ContentLayoutMoveRequest`, `ContentLayoutReplaceRequest`, `ContentLayoutDuplicateRequest`, `ContentLayoutWrapElementsRequest`, `ContentLayoutUnwrapRequest`, `ContentLayoutAttachRequest`, `ContentLayoutBindRequest`), each bound via `#[MapRequestPayload]`. Each carries the operation's parameters plus a required-but-nullable `expectedVersion` (the layout's `updatedAt`); the tree is loaded from storage, so there is no `layout` field, and `layoutId` is the route path argument.
- `LayoutDiagnosticsResultNormalizer` - Zero-dependency normalizer for the diagnostics half of an admin content response (the resolutions map and the diagnostics report). Invoked inside the `MutationResponse` and `DiagnoseResponse` factories so the diagnostics half of every admin content response shares one wire shape.
- `MutationResponse` - `\JsonSerializable` owning the mutation response wire shape (the seven keys `{ layout, resolutions, diagnostics, affectedElementIds, orphaned, droppedWiring, droppedProperties }`) for all eighteen draft + persisted mutation routes. Private constructor plus a `fromResult(MutationResult, StoredElementCodec)` factory; its overridden `jsonSerialize()` is the single definition of which fields are JSON maps (`resolutions`/`droppedProperties`, `{}` when empty) versus lists (`[]` when empty). Output-only: serialized to the HTTP response and discarded, never cached or denormalized.
- `DiagnoseResponse` - Sibling `\JsonSerializable` owning the resolve-and-diagnose wire shape (`{ resolutions, diagnostics }`). `fromReport(array $resolutions, DiagnosticsReport)` normalizes via `LayoutDiagnosticsResultNormalizer`, and `jsonSerialize()` casts the `resolutions` map to `{}`-when-empty, the same discipline as `MutationResponse`.
