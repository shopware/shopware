# Persisted Mutation Errors

The failure conditions specific to the persisted mutation actions ([persisted-mutation.md](persisted-mutation.md)).

In addition to the structural `400`s of the stateless endpoints (`mutationTargetNotFound`, `mutationCycle`, `mutationSlotRequired`, `mutationInvalidWrapTargets`, `mutationUnknownType`, `mutationPropertyUnknown`, `mutationPropertyConflict`, `mutationPropertyValueRejected`, `mutationPropertyLanguageKeyInvalid`, `mutationPropertyNotTranslatable`, `bindingSpecificationNotFound`, `bindingTypeMismatch`, `bindingRootSourceNotScoped`, `#[MapRequestPayload]` validation):

`mutationPropertyLanguageKeyInvalid` fires inside the operation, ahead of the DAL constraint pass, so it reports the first offending map key only. The per-key enumeration `PropertyTypeConformanceValidator` produces on a direct entity write does not apply on this route.

| Condition                                                                         | HTTP | Factory / source                                                                                                                            |
|-----------------------------------------------------------------------------------|------|---------------------------------------------------------------------------------------------------------------------------------------------|
| `{layoutId}` names no stored layout                                               | 404  | `contentLayoutNotFound`                                                                                                                     |
| `expectedVersion` does not match the layout's current `updatedAt`                 | 409  | `layoutVersionConflict` (no write)                                                                                                          |
| `insert-element`, `replace-element` or `attach-element` on a type whose default binding specification set holds more than one (only reachable via a database row created outside the app lifecycle) | 409 | `bindingSpecificationDefaultAmbiguous` (thrown before the repository write, so nothing is persisted)                                       |
| A binding specification the edit applies carries a `!scoped` config value, for a key the edit writes, with no entry for the persisted layout's root source ([full condition](mutation-errors.md)) | 400 | `bindingRootSourceNotScoped` (thrown before the repository write, so nothing is persisted) |
| `expectedVersion` is not a parseable date-time                                    | 400  | `invalidVersionToken` (no write)                                                                                                            |
| `translate-element`: the caller lacks the operation's declared write privilege `content_layout:translate` | 403 | `missingPrivileges` (`MissingPrivilegeException`, checked by `PersistedLayoutMutator::mutate()` before the layout is loaded, so it wins over `404`/`409`/`400` and nothing is read or written) |
| The committed edit breaks resolvability for a bound source, or is not well-formed | 400  | `ContentLayoutWriteValidator` rejects the `content_layout` write (`WriteException`); the binding-scope violations are in the error payload |
| Collective validation fails or a per-file/per-row load step raises the matching `*_LOAD_FAILED` code for an element-type, style-option, or binding registry | 500 | The corresponding `ELEMENT_TYPE_LOAD_FAILED`, `STYLE_OPTION_LOAD_FAILED`, or `BINDING_SPECIFICATION_LOAD_FAILED` error propagates instead of being relabelled as an invalid layout write |

Detached content (`orphaned`), dropped wiring (`droppedWiring`), and dropped property values (`droppedProperties`) are **left out of the commit and reported**. The stored tree omits them and the response returns them. The caller therefore re-places subtrees with `attach-element`, re-wires the keys, or re-applies the values. See [The module drops nothing silently and reports every loss](../../docs/principles/failure-and-loss.md#the-module-drops-nothing-silently-and-reports-every-loss).

Runtime definition failures also include invalid filenames and binding canonicalization/type errors (500 with their specific codes). Preset-loading operations additionally expose preset load and validation errors. See [definition-load errors](../../docs/definition-load-errors.md) for the code/status mapping and app-install distinction.
