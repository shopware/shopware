# Authoring Sugar and Canonicalization

An author can write a `resolves` entry in one of three shapes. `Serialization/BindingSpecificationCanonicalizer` expands the first two into the third at load time, between `Serialization/BindingSpecificationSerializer::denormalize()` and constraint validation. Both validators therefore only ever see canonical `{loader, config}` entries. Tier B and tier C name no loader source: both key off the loaders' declared config specifications (`Hydration/DataLoader/LoaderConfigSpecification`), so an extension loader that declares the same `ConfigKeyKind`s participates identically. Tier A is the one exception: it resolves directly to one of the two built-in resolvedBy loaders (`ResolvedByLoaderBranch`), a closed rule no loader-registry search can change.

- **Tier A: a bare property-reference string** (`media: mediaId`): the reference property's declared FQCN closes it to two branches. A subclass of `Entity` resolves to the built-in `entity` loader, a subclass of `EntityCollection` to the built-in `entity_collection` loader. Anything else is a hard load error naming the tier B/C fix. The string fills each loader's `property` key. No loader search runs, and installing an extension loader can neither expand nor break tier A. The FQCN-to-entity-name derivation for the loader's `entity` key (the branch-parameterized `deriveEntityName()`) still ranges over the open entity registry, see [entity-name-derivation.md](entity-name-derivation.md).
- **Tier B: the single-key loader form** (`media: { entity: { property: mediaId } }`): the one key names the loader source. Its value is the flat config. Every required `entityName`-kind key absent from that config is derived from the reference property's FQCN. A config key the loader does not declare is a load-time error.
- **Tier C: the canonical form** (`media: { loader: entity, config: { entity: media, property: mediaId } }`): passed through unchanged; the only shape for unusual configs.

Every specification the canonicalizer processes (sugared or already canonical) must declare a registered element type; an unknown type is a hard load error (`ContentSystemException::bindingSpecificationUnknownType`, 400). Any sugar that cannot expand deterministically (an unrecognized entry shape, a `loader` key mixed with a loader-source key, a tier-A reference FQCN that is neither an `Entity` nor an `EntityCollection` subclass, zero or several entities producing the FQCN, an unknown tier-B config key) is a hard load error (`ContentSystemException::bindingSpecificationCanonicalizationFailed`, 400) whose message carries the mechanical fix. Sugar never resolves by precedence ([failure-and-loss.md](../../docs/principles/failure-and-loss.md#a-component-throws-where-it-meets-invalid-data-and-nothing-degrades-silently)). `DatabaseBindingSpecificationLoader` never canonicalizes: app rows are persisted canonical by construction.
