## Constraints

- `load()` returns `ContentDataLoaderResult` on every path and throws nothing itself. Wrap each throwing collaborator call in `catch (ShopwareHttpException)`, never an enumerated union, and return `notFound()`. Let every other exception propagate. Check: does a collaborator call in `load()` sit outside the catch, or does a catch name another type? [data-loading.md](../../docs/principles/data-loading.md#a-loader-degrades-on-a-named-domain-outcome-and-lets-every-other-fault-propagate)
- Guard every config value a loader dereferences as an entity id with `Uuid::isValid()`, after its lowercasing or alias resolution and before first use. Take the loader's null-input path on failure. Check: can a `PropertyReference` value reach an id parser before the guard? [data-loading.md](../../docs/principles/data-loading.md#a-loader-degrades-on-a-named-domain-outcome-and-lets-every-other-fault-propagate)
- Read every loader input off `LoaderInputs`, never off the element or `$requirement->config` (kept for loaders keyed on `source`). Declare a static default in `ConfigKeySpecification`, a context-derived fallback as `hasDefault: false` applied in `load()`. Leave presence and type guards to `LoaderInputResolver`; a domain emptiness fallback (an empty-string activeId) stays in the loader. Check: does `load()` read the element or `$requirement->config`, or repeat a guard the resolver owns? [data-loading.md](../../docs/principles/data-loading.md#a-loader-consumes-typed-inputs-resolved-from-its-own-declared-specification)
- Declare `configSpecification()` from literals and constants, never from injected state. Check: does it read a constructor-assigned property? [README.md](README.md#build-time-validation)
- Keep a loader's `configSpecification()` required keys and its config serializer's `decode()` requirements in agreement, and pin it with a per-loader test modelled on `EntityCollectionLoaderTest::testConfigSpecificationRequiredKeysMatchSerializerRequiredKeys`. Check: does the loader's test compare the two key sets? [data-loading.md](../../docs/principles/data-loading.md#a-loader-consumes-typed-inputs-resolved-from-its-own-declared-specification)
- Use `$context->getContext()` for entity repository queries. Check: does a repository call in `load()` pass any other `Context`? [data-loading.md](../../docs/principles/data-loading.md#an-element-receives-a-sales-channel-context-value-only-from-a-loader-that-returns-that-value)
- Publish what an authoring client needs through introspection, so it never parses loader configuration or hardcodes root context. Check: would a client have to read `resolves` config or hardcode a root-source list to learn this? [data-loading.md](../../docs/principles/data-loading.md#an-authoring-client-reads-loader-configuration-through-introspection-and-never-parses-it)
