# Style Option Model

## Universal, Not Per-Type

Style options are strictly universal: every defined option is valid on every element, with no backend per-type gating. Where an element type declares its own `properties` and `slots`, a style option declares nothing about which elements it applies to. Visibility hints (for example, showing `col-span` only inside a grid) are carried in the option's opaque `adminUI` block. See [Presentation hints belong to the editor, and the server never branches on them](../../../../docs/principles/type-declarations.md#presentation-hints-belong-to-the-editor-and-the-server-never-branches-on-them).

This is why an option name lives in a **flat global namespace**: the name is the Store-API wire key (`col-span`), not a source-prefixed type name (`Sw:Grid`). Uniqueness is still enforced — by the loader and registry dedup at load time, by `StyleOptionCollisionDetector` at app install time, and by a DB `UNIQUE KEY` — only the prefix is dropped.

## The Option Model

- `StyleOptionSpecification` - the immutable declared contract of one option, keyed by its `name` (wire key). `breakpointAware` defaults to `true` (an option opts out with `breakpointAware: false`; no shipped core option does, so every shipped core option is breakpoint-aware); `true` makes the value a per-breakpoint map, `false` a single flat scalar. `toSchema()` serializes it for introspection and always emits `breakpointAware`.
- `StyleOptionValueType`: the value vocabulary: one canonical primitive (`string`, `integer`, `number`, `boolean`) plus declarative bounds (`enum`, numeric `range`, string `maxLength`) and a `default`. Style values are always primitives, so there is no FQCN, no nesting, and no regex; a `maxLength` (defaulting to 255 for an unbounded string or number) caps what a client can store in the layout JSON.
- `Breakpoint` - the fixed canonical key set `xs, sm, md, lg, xl, xxl`, returned by `Breakpoint::values()`. Per-breakpoint values are individually optional, so a responsive option may set only `md`. The mobile-first cascade is described in [option-yaml.md](option-yaml.md).
- `ElementStyle`: the per-element value object: an `option => (scalar | breakpoint => scalar)` map. A breakpoint-aware option holds a per-breakpoint map (`"col-span": {"md": 6}`); a flat option holds a bare scalar (e.g. a forward-looking `"z-index": 10`). A plain immutable DTO (not a `Struct`), emitted as a raw array through `toArray()` and omitted when empty. That shape is enforced at the DAL write boundary rather than by the object: `Layout/Codec/StoredTreeConstraints` derives the per-option constraints from the style option registry on every call and rejects an option the registry does not know, while the constructor stores what it is handed and `StoredElementCodec::decodeStyle()` cleans a stored map structurally without consulting the registry, so an option a provider has since removed still reads. The mutation subsystem aliases an untouched element's `ElementStyle` by reference into rebuilt and cloned nodes, so the object stays immutable.

A style option's `default` pre-fills the editor and is never applied at serve time. It reaches stored element JSON in one case: `ElementStyleNormalizer`, run at the write boundary by `Layout/LayoutWriteBoundary`, fills the missing breakpoints of a partially specified map from it. An option whose every value equals its default drops as unset. See [The module seeds a primitive default at write time, never at serve time](../../../../docs/principles/stored-model.md#the-module-seeds-a-primitive-default-at-write-time-never-at-serve-time).
