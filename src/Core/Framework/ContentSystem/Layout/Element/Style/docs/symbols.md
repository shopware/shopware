# Style Option Symbols

The symbol index for the style option system: each class, its role, and its path. The constraints that
govern editing them stay in [../AGENTS.md](../AGENTS.md), and the conceptual model in
[../README.md](../README.md).

- **Registry**: `Registry/AbstractContentSystemStyleOptionRegistry` (abstract, decoration pattern; strict `all()` / lenient `allResolved()`, both `array<string, StyleOptionSpecification>`, plus `invalidate()`), `Registry/ContentSystemStyleOptionRegistry` (stateless aggregator over loaders tagged `content_system.style_option_loader`), `Registry/CachedContentSystemStyleOptionRegistry` (`cache.system` pool decorator, cache keys `content_system.style_options` and `content_system.style_options.resolved`, both cleared on `invalidate()`)
- **Compiler Pass**: `Framework/DependencyInjection/CompilerPass/ContentSystemStyleOptionCompilerPass` (discovers core `Definitions/`, each bundle's and active plugin's fixed `Resources/content-system/style-options`, and dev-only active app directories; injects them into `YamlStyleOptionLoader`)
- **Loaders**: `Loader/AbstractContentSystemStyleOptionLoader` (base contract, `load(): list<StyleOptionSpecification>`), `Loader/YamlStyleOptionLoader` (filesystem; `loadDtosFromDirectory($directory, $source)` is reused by the app persister), `Loader/DatabaseStyleOptionLoader` (active app options in prod, empty in dev), `Loader/StyleOptionSourceDirectory` (`source`, `path` VO), `Loader/ResolvedStyleOptionSpecificationDto` (`name`, `source`, `dto`; `toSpecification()`)
- **Serializer**: `Serialization/StyleOptionSpecificationSerializer` (`denormalize` array → DTO, `normalize` DTO → array; `normalize` emits `breakpointAware` and `kind` only when `!== null`, like `enum` / `range` / `maxLength` / `default` — so an absent flag is omitted but an explicit `false` is kept on round-trip; this is the shape the app persister stores into `app_content_system_style_option.schema`, so `kind` survives install and reload)
- **Specification**: `Specification/StyleOptionSpecification` (const `KIND_BOX_SPACING`; `name()`, `valueType()`, `breakpointAware()`, `source()`, `kind()`, `toSchema()`; `toSchema()` always emits `breakpointAware` before `adminUI`, and does **not** carry `kind` — the introspection shape is unchanged), `Specification/StyleOptionValueType` (consts `TYPE_STRING|INTEGER|NUMBER|BOOLEAN`, `PRIMITIVE_TYPES`, `DEFAULT_STRING_MAX_LENGTH = 255`; `type()`, `enum()`, `range()`, `maxLength()`, `default()`, `isPrimitive()`, `toSchema()`), DTOs in `Specification/Dto/`
- **Constraint deriver**: `Validation/StyleOptionConstraintDeriver::derive(StyleOptionValueType): list<Constraint>` — emits via the fluent `DataAbstractionLayer/Write/Validation/ConstraintBuilder`; applies `NotBlank` to every type **except** `boolean` (false is a valid value), plus `Range` / `Length` / `Choice` from the declared bounds
- **Write constraints**: `Layout/Codec/StoredTreeConstraints::styleConstraints()` (the write boundary; branches on `breakpointAware()` per option — a breakpoint-aware option gets a per-breakpoint `Collection`, a flat one a single `Optional`. Both levels compose `NotNull` ahead of the derived constraints, because `Type` skips a null and a boolean option carries no `NotBlank` — without it the descriptor would admit a null value `decodeStyle()` refuses), reached from `Layout/Field/StoredElementListFieldSerializer::buildConstraints()`
- **Read**: `Layout/Codec/StoredElementCodec::decodeStyle()` is registry-free and structural — a scalar is kept flat, an array must be a non-empty map keyed by `Breakpoint::values()` with scalar values, and unknown options ride through verbatim. Every malformed shape throws (`invalidMapKey` for a non-string option name, `unknownStyleBreakpoint` for an unknown breakpoint key, `invalidFieldValueType` for a value that is neither scalar nor array, a non-scalar breakpoint value, and an explicitly empty breakpoint map); nothing is dropped. Strictness is structural, not registry-driven
- **API endpoints**: `Api/Controller/InfoController::getContentSystemStyleOptions()` (`GET /api/_info/content-system-style-options.json`) and the folded `styleOptions` key on `getContentSystemElementTypes()`
- **App integration**: `App/Aggregate/AppContentSystemStyleOption/AppContentSystemStyleOptionDefinition` (DAL entity, table `app_content_system_style_option`, `UNIQUE KEY` on `name`), `App/Lifecycle/Persister/ContentSystemStyleOptionPersister` (const `STYLE_OPTIONS_DIRECTORY = 'Resources/content-system/style-options'`; hash-based upsert/delete in one transaction, registry invalidation only after a committed change), `App/Lifecycle/Handler/ContentSystemStyleOptionLifecycleHandler` (persists on install/update; invalidates the registry on activate/deactivate/uninstall/local delete — activation does not pre-validate for a collision, since it cannot fail atomically after `active=1` is committed; `all()` surfaces a cross-loader collision loudly on the next write/install instead), `App/Validation/ContentSystemStyleOptionAppValidator`
- **Collision detection**: `Validation/StyleOptionCollisionDetector` (proposed names against the registry plus inactive app options; the DB `UNIQUE KEY` is the authoritative guard)
- **Value object**: `ElementStyle` (`array<string, string|int|float|bool|array<string, string|int|float|bool>>` of `option => (scalar | breakpoint => scalar)`; `final readonly`, `toArray()`, `isEmpty()`)
