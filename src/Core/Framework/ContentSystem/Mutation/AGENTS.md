## Source Code References

- `LayoutMutation` - The operation contract. `apply(array $tree): array` is a pure transform returning a NEW `list<ContentElement>`; it must not mutate `$tree`, any `ContentElement`, or any `SlotContent`. `affected(): list<string>`, `orphaned(): list<ContentElement>`, `droppedWiring(): list<string>`, `droppedProperties(): array<string, mixed>` report the change computed during `apply()`. Single-use: `apply()` must run before any reporter is read. `@internal`.
- `AbstractLayoutMutation` - Base implementing `LayoutMutation`. Holds the protected `$affected` / `$orphaned` / `$droppedWiring` / `$droppedProperties` stash plus their getters, and the shared protected tree-surgery primitives:
  - `findNode(array $tree, string $id): ?ContentElement` - recursive lookup across all slots.
  - `locate(array $tree, string $id): ?ElementLocation` - lookup returning node, index, and parent slot coordinates.
  - `subtreeIds(ContentElement $node): list<string>` - the node id plus every descendant id.
  - `removeSubtree`, `insertAtRoot(tree, ?index, nodes)`, `insertIntoSlot(tree, parentId, slot, ?index, nodes)`, `replaceNode(tree, id, replacement)` - path-copying tree edits, each returning a new `list<ContentElement>`.
  - `cloneWithNewIds(ContentElement $node): ContentElement` - deep clone reminting every id in the subtree.
  - `scaffoldElement(AbstractContentSystemElementTypeRegistry $registry, string $type, array $slots = []): ContentElement` - fresh element seeded with the type's primitive property defaults, no wiring.
  - `requireRegistered(registry, type): void` - throws `ContentSystemException::mutationUnknownType` when the type is unregistered.
  - `childList(ContentElement $node): list<ContentElement>` - every direct child across all slots, in slot order.
  - Private `locateInParent`, `spliceIntoNodeSlot`, `spliceList`, `mapSlots`, `rebuildNode` - all node reconstruction routes through `rebuildNode` (the `ContentElement` constructor). `@internal`.
- `ElementLocation` - `@internal final readonly`. `public ContentElement $node`, `public int $index`, `public ?ParentSlot $parent = null`. A `null` parent marks a root element, and then `$index` is the index in the root list.
- `ParentSlot` - `@internal final readonly`. `public string $parentId`, `public string $slot`.
- `MutationResult` - `@internal final readonly`. Constructor: `array $layout, array $resolutions, DiagnosticsReport $diagnostics, array $affectedElementIds, array $orphaned = [], array $droppedWiring = [], array $droppedProperties = []`. `$resolutions` is `array<string, list<PropertyResolution>>` keyed by element id; `$droppedProperties` is `array<string, mixed>` keyed by property key.
- `MutationPipeline` - `@internal`, with a `@final` annotation (behaviorally final, kept mockable for tests). Constructor: `LayoutDiagnostics $diagnostics`. `run(LayoutMutation $mutation, array $tree, ?array $rootContext, ?Context $context = null): MutationResult` applies the mutation to the already-decoded `list<ContentElement> $tree`, diagnoses the whole new tree, and restricts the returned resolutions to the affected set via `array_intersect_key($analysis->resolutions, array_flip($affected))`. Decoding the request draft is the caller's job (`Api/DraftLayoutDecoder`); the pipeline is agnostic to whether the tree came from a request draft or a loaded `content_layout`. Stateless: it never persists. The persisted counterpart is `PersistedLayoutMutator`.
- `PersistedLayoutMutator` - `@internal`, `@final` annotation. The persisted counterpart to `MutationPipeline`: it commits one mutation to a stored `content_layout`. Constructor: `LockFactory $lockFactory, EntityRepository<ContentLayoutCollection> $contentLayoutRepository, ContentElementFieldSerializer $elementSerializer, iterable<LayoutBindingEnumerator> $bindingEnumerators, LayoutDiagnostics $diagnostics`. `mutate(string $layoutId, ?string $expectedVersion, LayoutMutation $mutation, Context $context): MutationResult`: serializes concurrent writers for the layout id under a `lock.factory` named lock so the load → version-check → commit span is atomic (closing the lost-update window), loads by id (`ContentSystemException::contentLayoutNotFound`, 404, if absent), guards the optimistic-concurrency token against the row's `updatedAt` (`layoutVersionConflict`, 409, without writing on a mismatch; an unparseable token is a `400` `invalidVersionToken`; a `null` token matches a never-updated row), applies the op to the loaded `getLayout()` tree, then persists the serialized tree via `update()` (running the resolvability gates, which reject a binding-breaking edit) and returns the `MutationResult`. The response diagnostics are derived from the layout's real source bindings via the tagged `Binding/LayoutBindingEnumerator`s (the same the write gate uses): no binding → well-formedness only; multiple bindings → binding-scope violations unioned into one report, resolutions from the last bound source. Content the op detaches (`orphaned`), wiring it drops (`droppedWiring`), and static property values it cannot carry (`droppedProperties`) are never lost: the committed tree omits them and they ride back in the `MutationResult` so the caller can re-place them with `Op/AttachElement` (orphans), re-wire (dropped keys), or re-apply (dropped values).
- `Op/InsertElement` - `__construct(AbstractContentSystemElementTypeRegistry $registry, string $type, ?string $parentElementId = null, ?string $slot = null, ?int $index = null)`. `requireRegistered`; with no parent it scaffolds and inserts at root; otherwise `$slot` is required (`mutationSlotRequired`), the parent must exist (`mutationTargetNotFound`), then it scaffolds and inserts into the slot. `affected = [newId]`.
- `Op/RemoveElement` - `__construct(string $elementId)`. Target must exist (`mutationTargetNotFound`); removes the subtree. `affected = []`.
- `Op/MoveElement` - `__construct(string $elementId, ?string $newParentId = null, ?string $newSlot = null, ?int $index = null)`. The element must exist (`mutationTargetNotFound`); a move into itself or a descendant throws `mutationCycle`; a non-null new parent must also exist (`mutationTargetNotFound`). `affected = $newParentId === $oldParentId ? [] : subtreeIds($node)`. A move to the root (no `$newParentId`) needs no slot; a same-parent move may omit `$newSlot` (reuses the current slot); a move under a different parent requires `$newSlot`. `$index` is applied to the **post-removal** list — the element is lifted out before it is spliced back, so a same-parent "move to index N" counts the siblings that remain after removal, not their original positions (`spliceList` then clamps a null/negative/out-of-range index to append).
- `Op/ReplaceElement` - `__construct(AbstractContentSystemElementTypeRegistry $registry, string $elementId, string $newType)`. `requireRegistered($newType)`; the element must exist (`mutationTargetNotFound`); keeps the id, carries over primitive properties whose key and type match, wiring (data requirements, providers, consumers) keyed to a non-primitive new-type property, and children of slots present in the new type. `orphaned` = children of slots absent from the new type; `droppedWiring` = old wiring keys minus kept; `droppedProperties` = static property values whose key is absent from the new type or whose value its property type rejects; `affected = subtreeIds($replacement)`.
- `Op/DuplicateElement` - `__construct(string $elementId, ?int $index = null)`. Target must exist (`mutationTargetNotFound`); deep-clones with new ids; `affected = subtreeIds($clone)`; splices at `$index ?? location.index + 1`.
- `Op/WrapElements` - `__construct(AbstractContentSystemElementTypeRegistry $registry, array $elementIds, string $containerType, ?string $slot = null)`. `requireRegistered`; slot required; each target must exist (`mutationTargetNotFound`); the targets must all be siblings in one slot (or all roots), else `mutationInvalidWrapTargets`; an empty id list also throws `mutationInvalidWrapTargets`. Scaffolds the container with the targets (in original order) in `$slot`, places it at the lowest target index. `affected = [containerId, ...elementIds]`.
- `Op/UnwrapElement` - `__construct(string $containerElementId)`. The container must exist (`mutationTargetNotFound`); `affected` = the union of `subtreeIds` over each child; removes the container and hoists its children (flattened across all slots in slot order) into the container's parent slot at the container's index. Reports the removed container's own static property values via `droppedProperties` and the wiring it consumed — its data requirement keys plus accepted-context keys, de-duplicated — via `droppedWiring`, so neither is silently lost; the context the container *provided* is not reported (see the carve-out below).
- `Op/AttachElement` - `__construct(AbstractContentSystemElementTypeRegistry $registry, ContentElement $element, ?string $parentElementId = null, ?string $slot = null, ?int $index = null)`. `requireRegistered($this->element->getComponent())` (the supplied root's component must be a registered type, else `mutationUnknownType`, matching the check insert/replace/wrap run); splices a caller-supplied subtree into `$parentElementId`'s `$slot` at `$index` (root when no parent), reminting every id via `cloneWithNewIds` (clients never supply ids; the server-minted ids come back in `affected = subtreeIds($clone)`). Mirrors `Op/InsertElement`'s placement (slot required with a parent → `mutationSlotRequired`; parent must exist → `mutationTargetNotFound`) but places the supplied subtree instead of a scaffold. Detaches nothing: `orphaned`/`droppedWiring`/`droppedProperties` stay empty. The inverse of a `ReplaceElement`'s detachment — re-attach its `orphaned()` subtrees, or paste a copied one.

## Constraints

- Immutability is the core invariant: `apply()` MUST NOT mutate the input tree, its elements, or any `SlotContent`; every transform reconstructs nodes through the `ContentElement` constructor (`rebuildNode` / `cloneWithNewIds` / `scaffoldElement`).
- The immutable node-rebuild idiom (`rebuildNode` plus the path-copying surgery in `AbstractLayoutMutation`) is intentionally NOT shared with `Output/ElementTreePruner::reconstructFromBottom`. The two echo each other but live in different layers with opposite intents — a mutation rebuilds to edit a tree, the pruner rebuilds to extract a partial-render subtree — so collapsing them would couple the two layers for a surface-only similarity.
- That invariant is upheld by convention, not enforced by the type: `ContentElement extends Struct` and is mutable (public `setProperty` / `setProperties` / `setContextDefinitions`). `apply()` reuses untouched input nodes in the result tree by reference, so the result aliases the input. This is safe today because nothing downstream mutates a result node — the diagnostics pass and the field serializer are read-only — but an in-place mutation of a result node would corrupt the input it aliases. Reconstruct result nodes (never mutate them in place), or deep-copy a node before mutating it.
- A mutation is single-use: `apply()` computes the `affected` / `orphaned` / `droppedWiring` / `droppedProperties` stash, so it must run before any reporter is read, and an instance is not meant to be re-applied to a second tree.
- `affected()` is a conservative highlight hint, not the correctness output. The authoritative result is `MutationPipeline`'s `LayoutDiagnostics` pass over the whole new tree; the pipeline only uses `affected` to narrow which resolutions the result carries.
- No silent loss: a subtree an operation detaches is always returned via `orphaned()`, a wiring key it cannot re-home via `droppedWiring()`, and a static property value it cannot carry over via `droppedProperties()` (a `ReplaceElement`'s new type cannot hold it, or an `UnwrapElement` removes the container that held it). None is discarded or silently re-mapped.
- `droppedWiring` carries reference keys an operation could not re-home. It is populated by `ReplaceElement` (keys with no matching reference property on the new type) and by `UnwrapElement` (the removed container's own data requirement and accepted-context keys, which the hoisted children cannot inherit). The carve-out is narrow: the context an unwrapped element *provided* to its descendants is ancestor context, not a wiring key it could re-home, so it is not a `droppedWiring` entry. A hoisted descendant that depended on that provided context instead surfaces as a `ViolationCode::BrokenRequiredChain` binding violation in the diagnostics pass when a source is bound. This is intentional, not a silent loss.
- Affected-set rules are load-bearing — do not weaken them (rationale in `README.md`, "Affected-set rationale"): `RemoveElement` reports none; `MoveElement` reports the moved subtree only on a parent change; `ReplaceElement` reports the whole reconstructed subtree; `UnwrapElement` reports the whole hoisted forest.
- Structural impossibilities fail `400` via `ContentSystemException`: `mutationTargetNotFound`, `mutationCycle`, `mutationSlotRequired`, `mutationInvalidWrapTargets`, `mutationUnknownType`. These are mutation-specific structural errors and are NOT client-defect codes (not in `CLIENT_DEFECT_CODES`).
- `MutationPipeline::run()`: `$tree` is the already-decoded `list<ContentElement>`; `$rootContext` is the bound source's root-ambient context (`list<ProvidedContext>`) or `null` for the well-formedness-only subset; `$context` is nullable with a `null` default. The request draft is decoded upstream by `Api/DraftLayoutDecoder` (structural pre-gate, shared with the preview and diagnose routes), not by the pipeline.
- `ReplaceElement::carryProperties` keeps a property only when its key matches a new-type property AND the value matches that property's declared primitive type; `carryWiring` keeps an entry only when its key matches a non-primitive (reference) new-type property.
- `WrapElements` containers provide no context of their own; wrapping changes the wrapped elements' nesting scope but adds no provider.
