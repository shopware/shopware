## Constraints

- `ElementResolver::pickDefault()` is conservative over three ordered pools: exactly one `Root` candidate wins; more than one `Root` returns `null` with no fallback to a `Parent` candidate; with no `Root` candidates, exactly one `Parent` candidate wins and more than one returns `null`; absent both, exactly one config-complete loader candidate wins. Otherwise returns `null`: the diagnostics layer maps `null` for required properties to `ambiguous_required`/`unresolved_required`
- `ResolutionCandidate::configComplete` (loader candidates only) is `true` only when the capability's derived completion residue (`ContentSystemDataLoaderMap::residualConfigKeysFor()` — the loader's declared `LoaderConfigSpecification` required keys minus the `configTemplate` keys) is empty **and** the loader's config serializer decodes the capability's `configTemplate` without a client-defect `ContentSystemException`; a client-defect decode yields `false`, any other exception propagates (`ElementResolver::isConfigComplete()`)
- `ElementResolver::storedCandidate()` is applied wiring, not a candidate: a `Stored` requirement whose produced type resolves and is assignable to the declared FQCN becomes `resolved` directly (`$stored ?? pickDefault(...)`), never a `candidates` menu entry. A config that fails to resolve (client defect) or resolves to a mismatched type yields no `Stored` candidate — `Diagnostics/LayoutDiagnostics` reports the former as `InvalidConfig`, the latter as `MismatchedReferenceType`. A `string`-only `resolve()` call never produces a `Stored` candidate, because only a `StoredElement` instance carries `dataRequirements`
- `AvailableContextResolver` is section-agnostic: entity assignment yields page entity as root context; header/footer yield an empty `$rootContext`; the caller decides what to pass
- `PropertyResolution::candidates` contains both context candidates (`Parent` and `Root`, in availability order) and loader candidates (context offers first, loaders appended); `resolved` is the `pickDefault` selection, which may differ from the persisted assignment
- `AvailableContextResolver::resolve()` returns an empty list in two cases: `$targetElementId` is not found anywhere in `$tree`, **or** the element is found, `$rootContext` is empty (e.g. header/footer), and its ancestors expose no provider and re-broadcast no inflowing redistribute key. An empty result therefore does not by itself distinguish "element not in tree" from "no context available"
- `AvailableContextResolver::resolve()` mirrors runtime redistribution rather than unioning every ancestor's declared providers: walking the ancestor path top-down from an EMPTY incoming set, each ancestor exposes to the next position only (a) its declared providers whose own property resolves on it (backed via the shared `ElementResolver` against the chain incoming plus only those root-ambient entries the ancestor's own `ConsumerScope::Root` consumers write to that provider's key: the property key the consumer writes, `propertyAlias ?? consumerKey`, compared VERBATIM against the provider key, and the ambient key matching the consumer key by `ContextPathResolver::matches()`), so a provider filled through the element's own root-scoped consumer counts while a consumer-less ancestor's provider is not backed by a type-matching ambient entry. The written property key is compared verbatim because `Rendering/ContextDeliveryResolver::overlayRootContext()` writes it verbatim: a dotted consumer key carrying no `propertyAlias` writes the FULL dotted key, which no provider key reads, so it backs nothing; the same consumer under a `propertyAlias` equal to the provider key does back it. And (b) the keys it re-broadcasts via `redistribute: true` consumers whose key is present in its own CHAIN incoming context (re-exposed under `consumerAlias` when set). Both exposure branches mint `root: false`
- `AvailableContextResolver::resolve()` silently omits any ancestor provider whose declared property type is primitive (`isPrimitive()`): only Reference (FQCN-typed) provider slots become `ProvidedContext` entries, so a primitive-typed slot does not appear in the available-context list even though `getProvidesContext()` yields it
- `ElementResolver::resolve()` returns an empty list (not a list of unresolvable `PropertyResolution`s) when the element's component type is not registered in the type registry — no resolution is attempted for an unknown type
