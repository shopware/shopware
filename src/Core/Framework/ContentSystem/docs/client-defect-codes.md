# Client-Defect Error Codes

Which `ContentSystemException` codes mark a defect in client-supplied layout input rather than an
internal fault, and what reads that distinction.

- Client-defect classification: `ContentSystemException::isClientDefect()` (`CLIENT_DEFECT_CODES`) marks the error codes that signal a defect in client-supplied layout input: a typo'd entity (`UNKNOWN_LOADER_ENTITY`), undecodable/invalid config (`INVALID_FIELD_VALUE_TYPE`), a field value outside its permitted range (`INVALID_FIELD_VALUE_RANGE`), an unregistered source (`DATA_LOADER_NOT_REGISTERED`, `CONFIG_SERIALIZER_NOT_REGISTERED`), an element-definition context-wiring violation (`CONSUMER_ALIAS_WITHOUT_REDISTRIBUTE`, `PROPERTY_ALIAS_WITH_DOT_NOTATION`, `PROPERTY_ALIAS_COLLISION`, `REDISTRIBUTE_DOTTED_PATH`, `REDISTRIBUTE_CONFLICT`, `ROOT_SCOPE_WITH_REDISTRIBUTE`; the last four's enforcement sites: [Layout/Element/Context/AGENTS.md](../Layout/Element/Context/AGENTS.md)), a child-facing provider-key collision (`PROVIDER_DELIVERY_COLLISION`), a numeric wiring key (`INVALID_MAP_KEY`), or an element id outside the decode gate's value domain (`INVALID_ELEMENT_ID`), rather than an internal fault. `Diagnostics/LayoutDiagnostics` catches only these per element and maps them to a `ViolationCode::InvalidConfig` violation; every other code propagates, so an internal fault is never relabelled as the client's mistake. A status-code filter is insufficient: some HTTP 500 codes (e.g. `DATA_LOADER_NOT_REGISTERED`, `INVALID_FIELD_VALUE_TYPE`) are legitimate client defects for a client-supplied tree. The `UpdateElementProperties` property codes `MUTATION_PROPERTY_UNKNOWN`, `MUTATION_PROPERTY_CONFLICT` and `MUTATION_PROPERTY_VALUE_REJECTED` are mutation structural errors, not client defects, and are absent from `CLIENT_DEFECT_CODES`.
