# Element Styles

The universal per-breakpoint style options every element may carry, and where an element's `style` value
is stored, validated and served.

- **Style Option Registry**: `Layout/Element/Style/Registry/ContentSystemStyleOptionRegistry` (decoration trio, `cache.system`) aggregates the `content_system.style_option_loader`-tagged loaders whose YAML directories `Framework/DependencyInjection/CompilerPass/ContentSystemStyleOptionCompilerPass` discovers. Universal per-breakpoint presentation options (alignment, span, spacing, display) settable on every element; one registry feeds both validation and introspection. App options persist to `app_content_system_style_option` via `App/Lifecycle/Persister/ContentSystemStyleOptionPersister`. See [Layout/Element/Style/AGENTS.md](../Layout/Element/Style/AGENTS.md)
- **Element style storage**: each element's `style` inside the `content_layout.layout` JSON (no separate column) is encoded and decoded through `Layout/Codec/StoredTreeCodec`; `Layout/Codec/StoredTreeConstraints` composes the write-time constraints against the registry (the strict write rejects unknown options, mirroring the element-type system's unknown-`component` handling). Carried through every structural edit by the `Mutation/` ops, and onto the wire out of `RenderedElement::$style` by `Output/Encoder/ContentPageEncoder` (full format) and `Output/Encoder/ContentDecomposedPageEncoder` (decomposed), and through `Output/Struct/ContentSkeletonElement` for the skeleton format; omitted when empty in all three, and absent from the data format, which serves no structure
